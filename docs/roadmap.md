> **有没有真实跑过的证据**（会话产物 / 截图 / 代码路径），而不是"提示词里写过"。

### B 档 · 提示词已具备，但**条件触发**，未跑示例图不出现

这些写进了 `agent/managed_agent_system_prompt.md`，逻辑成立、不需要改代码；
但**当前四张关键帧与两张整卡里没有它们**——因为演示用例没命中触发条件。
评委若在卡片里找不到，答案就是这一节，而不是"其实没做"。

| 能力 | 触发条件 | 为什么已发布卡片里没有它 |
|---|---|---|
| **审美平替**（同调性、更可达的成本梯度投影，并写明哪一维让步） | 心动成本与预算/天数/出发地明显错配 | 嘉兴用例是"上海出发 + 高铁 23 分钟 + 中等预算"，本来就**不存在错配** |
| **同行结构投影**（情侣/亲子/独行 → 不同住宿档型、步行量、节奏） | 同行结构发生变化 | 演示只跑了"2 人情侣"一种结构 |
| **拍摄窗口 shot_window**（把"色调光线"翻译成到位时间） | 景点对光线敏感 | 属可选字段，旧版关键帧未输出 |
| **季节时差**（主体过季 → 给同月可兑现的**同款情绪**替代） | 画像季节感 ≠ 出行日期 | 11-08 出发看深秋水乡，正好同季 |
| **心动的代价**（用真实差价摊开氛围成本） | 氛围可量化为成本差 | 该用例未触发 |
| **跨媒介解构**（动漫/游戏/海报的渲染美学，仍走 7 维；取景地强制标注"未核实"） | 输入为二次元/游戏帧 | 演示未用此类图 |
| **无图退化路径**（只给一句感觉描述也能解构，标注依据弱一档） | 用户没图 | 演示都有图 |

> **复现成本极低**：上面 7 项中，前 5 项换一次输入参数即可在百炼控制台跑出来（各约 1~3 分钟），
> `agent/console_checklist.md` 已写好"条件出现"的核对口径与加演话术。

### C 档 · 设计推演，**本版本主动不做**（附原因，不是遗漏）

| 设想 | 为什么不做 |
|---|---|
| **相似图 → 交友 / 组队** | ① 用户相册与收藏是个人数据，跨用户二次利用需单独同意，与本产品"连照片 EXIF/GPS 都不解析"的隐私原则直接冲突；② 冷启动：没有用户基数时演示不出来，属"只能讲不能跑"的功能；③ 陌生人社交是强监管领域。**→ 降级为 C1 的匿名聚合，不做匹配撮合。** |
| **AI 生成"你该存的图"** | 会把作品从"审美解构"拖进"文生图"红海，且引入生成内容合规问题。 |
| **硬编码具体日出日落时刻 / 花期日期** | flyai 不返回该数据，另接数据源会开天窗并违背"不编造"。→ 只给通用光线规律与"以当年花期为准"。 |
| **行程中断救援 / 改签重排** | 赛道已有作品，且与"从灵感到出发"的定位越界（README 已明确不做）。 |
| **三档预算自动比价** | 同赛道标配；本作品的"平替"是**跨城市的审美投影**，不是同目的地比价，二者不要混称。 |

## 二、C1 · 我认为最值得做的下一步：**审美供给索引**

单张图的闭环已经跑通，下一步不该是"更多功能"，而是**把审美变成可检索的资产**。

- 每张心动旅行卡都会沉淀出一份**结构化 7 维向量**（`outputs/*/bundle.json` 里已有该字段）。
- 匿名聚合后，可以把站内商品按**氛围**而不是**景点类型**重新组织：
  不是"古镇 → 西塘"，而是"**暖金逆光 + 私密 + 极慢 + 深秋** → 这些真实房态"。
- 对用户：解决"说不清想要什么"；对平台：**把一次种草变成可归因的交易**。

**这才是这个入口真正的商业假设**——但请把话说准，别说过头：

> ❌ 不成立的版本："没人按感觉索引旅行。"
> ✅ 成立的版本：**内容平台已经按兴趣组织了"人"和"内容"，但旅行商品的供给侧索引仍是目的地 / 类目 / 星级；"感觉"这一层还没有可检索字段。** Vibe2Trip 的 7 维画像就是那个字段的候选形态。

这个区分很重要，因为**同一份报告既支持我们的论点，也证明了巨头已经在做这件事**——把它说成空白地会被评委一句话推翻。

### 商业闭环三件套（写进评审的市场前景栏）

1. **带参预订链接**：卡片每条预订入口带来源参数，可直接量化「感觉 → 下单」的转化率——把审美从玄学变成指标。
2. **分享回流**：心动旅行卡本就是自包含 HTML 长卡（`docs/demo/*.html`），截图即海报，天然适合小红书回流；卡上带二维码回到"上传你的图"入口。
3. **返佣**：预订入口即飞猪商品链接，可接推广伙伴分成。

## 四、同赛道坐标（2026-10-19 对已提交作品的实扫）

把自己放回真实赛道里估，不空喊"我们最独特"。以下**按入口类型**归类同赛道的常见做法，只谈路径差异、不评高下——每类都有各自最合适的场景。

**同赛道作品按入口大致分四类**：

| 入口类型 | 典型走向 | 与我们的关系 |
|---|---|---|
| 行前规划 / 比价 | 跨日期总价最优、一句话→可编辑备忘录、酒店多维裁决 | 我们**主动不做**的红海，这块已被做得很深 |
| 行中核验 / 救援 | 订单截图→冲突核验、行程中断重排、可审计闭环 | 我们在正文里区分的对象；其工程严谨度是标杆 |
| 人群 / 场景特化 | 亲子研学分龄讲解、公益游学、目的地语言防坑、演出单场次全程 | 头部物料区：多数有**线上站点 + 录屏视频** |
| 非文字兴趣信号 | 游戏口味→映射表、实景拍照→讲解、内容脚本生成 | **与我们概念最邻近**，分野见正文的对表 |

**我们相对稳的位置**：入口是**用户事先存下的灵感图**，且中间立了一个**结构化 7 维画像**——这两点的组合在同类入口里较少见。

**但必须承认的三处落后**（写下来，别等评委问）：

1. **没有录屏视频**。同赛道不少作品有 2~4 分钟成片（含视频站链接），个别还是竖屏精修。视频的说服密度顶得上五张截图——这是我们最该补、成本最低的一块（本轮按约定不做）。
2. **在线 Demo 只能看与照抄复现，不能在浏览器里真跑**。对比：有作品提供可直接填写的表单 / 公开体验入口 / 输入任意城市实时出结果。我们用「三步自助复现」把门槛压到三次复制粘贴，但**这不等于"免配置可体验"**，评委的验证成本仍然更高。
3. **flyai 集成深度不如几份硬核作品**：有作品摸清了限流 QPS、451 行为风控、加白流程、缓存熔断与密钥库签名冲突；我们只做了基础检索 + 城市级回退。若被追问工程纵深，这是短边。

**因此策略是**：把火力全部压在"入口独特 + 7 维画像可复算 + 感觉有标价"这条叙事上，**不去和头部比物料数量**；同时用这一节的诚实自评，主动说明我们与相邻做法的关系。
