# 🎨 Vibe2Trip ·「这张图的感觉，帮我安排」

> 2026 飞猪 AI 旅行创新大赛 · 参赛作品（自由方向）
> 一个**旅行审美解构师**：用户甩一张心动的灵感图，Agent 把它解构成旅行审美画像，再翻译成飞猪上真实可预订的目的地与行程。

## 这是什么

旅行决策最大的卡点是"不知道去哪"。但用户其实**已经知道自己喜欢什么感觉**——相册里存的那张风景照、想去的电影剧照、收藏的一条小红书、一张海报。
传统助手要么让你打字描述需求，要么让你玩测评猜人格。**Vibe2Trip 直接读你已经心动的那张图**：
用多模态模型把它解构成 7 个旅行审美维度（地貌/色调/氛围/活动/节奏/季节/人文自然比），形成一份「旅行审美画像」，
再映射到**飞猪官方 flyai 的真实库存**，产出「心动解读 + 命定目的地 + 按天行程 + 可预订清单」。

一句话价值：**你已经心动过那张图，我帮你知道它对应哪里、怎么去、住哪、玩什么。**
再往深一层：**你要的从来不是一个景点，是一种感觉——而这种感觉是有标价的。** 本作品做的就是把"感觉"拆成 7 个可检索维度，再用飞猪真实库存给它标上价格、日期与机位。

> **在线 Demo（单文件自包含，一个页面看完）**：https://qq1308194619.github.io/vibe2trip/demo/
> 一个 `index.html` 内含：① 两张**可交互**心动旅行卡（srcdoc + base64 双内嵌，点「打开完整卡片」即全屏）；② 案例① 金色江南水乡 → 苏州、案例② 冷调雪岭暖窗 → 阿勒泰，两种相反气质证明泛化（这两张整卡出自 **v1 本地管线** `qwen-vl`+`qwen-plus`；下方「三轮活体复现」是 **v3 控制台 Managed Agent** `Qwen3.8` 对同类水乡图核验后改判黄山宏村——两套管线、两个版本、各自真实，同一种感觉在不同运行里落到不同目的地属正常，故并列保留、不改图）；③ **4 张真跑关键帧**（图片以 data URI 内嵌，离线可看）；④ **「三步自助复现」区**，提示词与命令预填、一键复制。
> 纯静态、不依赖同目录其他文件，本地双击即可打开；不伪装成在线真跑——真跑需你自己的百炼 Key。

## 差异化（讲清楚入口选择，不评判他人做法）

旅行 AI 的入口可以是很多种：预算对比与跨日期比价、行中中断救援/改签、读订单截图核对已有行程、一句话生成行程、酒店裁决、研学讲解、语言防坑、内容脚本生成——每一种都解决了各自场景里真实的问题。
Vibe2Trip 押的是**另一条入口**——**从"审美/氛围图"反解旅行**：

- 输入不是文字、不是订单截图、不是测评答案，而是用户**主动存下的、让他心动的那张图**。
- 核心在"**审美解构 → 供给映射**"这层翻译，以及中间那个**显式、结构化、可复算的 7 维画像**（不是一串模型心里的形容词，而是能逐条回溯"命中哪一维"的字段）。

**两条最容易与本作品混淆的路径，这里只谈走向差异、不评高下**：

| 容易混淆的路径 | 它的走向 | 与 Vibe2Trip 的关系 |
|---|---|---|
| 在**现场**拍实景照片求讲解 | 人在现场 → 认建筑/文物 → 生成解说 | 场景互补：它解"我眼前这是什么"（行中），本作品解"我下次想去哪"（行前）——输入是**事先存下的灵感图**，输出是**还没出发的行程** |
| 报**游戏/兴趣名**映射成主题地图 | 文字标签 → 查人工维护的口味映射表 | 映射表做法对已覆盖的对象稳定、可解释；本作品选择**不维护表、直接读像素**：冷门番、新出的游戏、说不清出处的截图也能接住，扩展性来自模型视觉能力 |

## 对标评分维度

- **创新性 40%**：多模态 + 审美/空间感知，入口从"打字 / 测评"换成"一张你早就存下的图"（与相邻路径的分野见上表）；且把"审美"做成了可检索的结构化中间表示，而不是一句文案。
- **完整度 30%**：核心闭环"灵感图 → 审美画像 → 真实可预订行程"一条命令当场可演示；价格/房态/航班全部来自 flyai 真实返回，稳定可验证、不编造。四张关键帧 + 两张整卡 + 全文产物 + 静态在线演示齐备。
  - 已知短板（不藏）：**没有录屏视频**，且在线演示**只能看与照抄复现、不能在浏览器里真跑**。
- **市场前景 30%**：命中"不知道去哪 + 收藏了一堆灵感图却落不了地"的高频刚需，且**这条迁移有官方数据可查**：
  - 文化和旅游部《2025 年文化和旅游发展统计公报》（2026-06-02）：2025 年国内居民出游 **65.22 亿人次（+16.2%）**、出游总花费 **6.30 万亿元（+9.5%）**。
  - 飞猪 × 小红书《"五一"出行趋势报告》（2026-05，中国经济网/新浪财经转载）：**69% 的用户基于兴趣决定出行目的地**；"出片党"因**影视取景地、课本同款风景地**锁定目的地，旅拍"已成刚需"；**飞猪 AI 咨询量"五一"较清明继续增长 56%**，"来自 AI 的建议"成为决策关键变量。
  - 小红书《2026 兴趣游趋势报告》（中国日报网 2026-09-24 转载）：**体验型旅游搜索环比 +48%，是"打卡型"搜索增速的 1.6 倍以上**，"用户不仅搜索去哪里，也在寻找到那里可以做什么"。⚠️ 平台自披露口径，非独立审计。
  - 商业闭环：接入飞猪推广伙伴返佣；更关键的是**每张卡沉淀一份结构化 7 维画像**，可聚合为**「审美供给索引」**，让商品按**氛围**而非景点类型被检索，并用带参预订链接量化「感觉 → 下单」转化（推演见 `docs/roadmap.md`）。

## 能力分三档（别把设想当成果）

> 我们把"诚实"当**底线而不是卖点**（同赛道里我们把"诚实"做到极致的作品见过不少——明确声明"不把模拟接口当真实证据"、给每条数据标出处的做法，都给了我们提醒）。底线之下的东西不吹，底线之上的差异化靠那句立场：**把一种感觉标上真实价格。** 能力分级完整清单见 [`docs/roadmap.md`](docs/roadmap.md)：

- **A 档｜已真跑、有截图与产物**：灵感图 → 7 维画像 → 城市级目的地 → flyai 真实数据 → 排满每天 → 心动旅行卡六段 + 真实预算口径；另有相反气质案例②（雪岭暖窗 → 阿勒泰）证明泛化。
- **B 档｜提示词已具备，但条件触发**（示例用例没命中就不会出现，换参数即可跑，无需改代码）：
  审美平替（成本梯度上的同调性投影）、同行结构投影（情侣/亲子/独行重排）、拍摄窗口（光线→到位时间）、季节时差（主体过季给同款情绪替代）、心动的代价（用真实差价摊开氛围成本）、跨媒介解构（动漫/游戏帧仍走 7 维，取景地强制标注未核实）、无图退化路径（一句感觉描述也能解构）。
- **C 档｜主动不做并给原因**：跨用户相似图匹配（交友/组队）与"连照片 EXIF 都不解析"的隐私原则冲突、且冷启动无法演示 → 已降级为 C 档的匿名聚合设想。

> 设计纪律：**新能力一律做成条件分支，不改卡片必选结构**。已发布的截图、示例卡、在线 Demo 到今天仍与提示词完全一致。

## 技术栈与运行环境（已验证）

- **大脑（审美解构 + 行程编排）**：阿里云百炼
  - Managed Agent（主路径）：Qwen3.8-Max / Qwen3.8-Flash 原生多模态。
  - 本地离线复现：DashScope OpenAI 兼容接口，读图解构 `qwen3-vl-plus`（多模态）、行程编排 `qwen-plus-latest`。
- **真实旅行供给**：飞猪官方 `@fly-ai/flyai-cli`（flyai skill 的执行体）。
  其 `dist/flyai-bundle.cjs` 是**自包含 bundle，仅依赖 Node 内置模块**，因此**无需 npm/npx**，`node` 直接运行即可拿到飞猪真实库存。
  （flyai 后端为 MCP server `https://flyai.open.fliggy.com/mcp`，带签名鉴权，故无法被通用 MCP 客户端直接挂载；本作品用官方 bundle 作为执行体，是最稳的接入方式。）
- **运行要求**：Node ≥ 18（仅 node 可执行文件即可，不需要 npm）。
- **flyai CLI 版本（重要，会影响你能拿到哪些字段）**：本仓库脚本用法示例给出的版本是 **1.0.16**，建议用 `node scripts/setup_flyai.mjs --version 1.0.16` **固定复现**（安装后确切版本会写入 `vendor/flyai/VERSION`）。
  flyai 各命令的字段覆盖**随 CLI 版本与 Key 模式变化**。可用 `FLYAI_API_KEY=你的Key node scripts/probe_flyai.mjs` 一键复测；**2026-10-20 正式 Key 实跑结果**：`search-train` 有真实座席票价、`search-poi` 有真实票价（乌镇西栅 ¥147，与已发布卡片一致）、`search-hotel` 有真实房价与 `star` 档次，但 **`rate` 评分未返回**——所以卡片不展示评分列。旧版 CLI（如 1.0.5）连火车查询命令都没有，体验模式 Key 则会把酒店价格掩码成 `¥1xx`。**同一字段"有没有"在不同记录里会不一致，根因就是版本与 Key 模式，而非谁在编数据**。本作品因此只写原始返回值，查不到就地标注"未返回"，绝不跨字段推断。
- **凭证**（写入 `.env`，已 gitignore）：
  - `DASHSCOPE_API_KEY`：百炼 API-KEY（必填，驱动 Qwen-VL/Qwen）
  - `FLYAI_API_KEY`：飞猪正式 Key（选填；不填则用 flyai 内置"体验模式"——商品与预订链接真实，但价格掩码如 `¥1xx`）

## 快速开始

```bash
# 0) 准备 flyai 执行体（无需 npm，自动下载官方 bundle 到 vendor/）
node scripts/setup_flyai.mjs

# 1) 配置密钥
cp .env.example .env   # 然后填入 DASHSCOPE_API_KEY（必填）与 FLYAI_API_KEY（选填）

# 2) 一条命令跑通全链路：读图审美解构 → 飞猪真实数据 → 心动旅行卡
node scripts/vibe_trip.mjs --image assets/demo_inspiration.png \
     --from 上海 --date 2026-11-08 --days 3 --people "2人情侣" --budget 中等
# 产物：outputs/<目的地>_<日期>/card.html + card.md + bundle.json
# 预算口径：住宿为"每间每晚"、交通为"每人每段"；卡片按同住人数分摊住宿，
#          同时给出 N 人合计与人均（同住人数从 --people 推断，也可用 --party 3 显式指定）。
```

其他模式：

```bash
# 复用已解构的画像（不重复消耗 VL token），只重跑真实数据与排版
node scripts/vibe_trip.mjs --vibe assets/vibe_hangzhou.json --from 北京 --date 2026-11-08 --days 3

# 离线演示排版逻辑（占位示例数据，显著标注 SAMPLE，非真实）
node scripts/vibe_trip.mjs --sample

# 参考实现：纯 Python 标准库的组装器（把 bundle JSON 渲染成 Markdown 卡）
python3 scripts/build_vibe_trip.py --bundle outputs/xxx/bundle.json
```

## 诚实边界

- 酒店/机票/景点/价格**全部来自飞猪 flyai 的真实返回**；脚本层只做聚合、排序、排版，不产生任何价格或商品数据。
- 未配置正式 `FLYAI_API_KEY` 时为飞猪**体验模式**：商品名/预订链接/航班号真实，但**价格被掩码**（如 `¥1xx`），此时卡片会显著标注且不计算预算区间，绝不把掩码当真实价格。
- `--sample` 模式中的数字是**占位示例**，仅用于离线演示排版逻辑，运行时显著标注，绝不代表真实飞猪数据。
- 审美解构只描述图中**真能看出来的**维度；认不出具体地点时如实说明并给"神似候选"，不把猜测伪装成事实。**动漫/游戏帧同理**：可提作品名，但取景地一律标注「疑似取景地（二次元推测，未核实）」，虚构地名绝不进 `recognized_place`。
- 拍摄窗口只给**通用光线规律**（日落前逆光、开园首批客人最少），**不编造具体日出日落时刻与花期日期**——flyai 不返回这类数据，宁可让用户自行核对。
- 本作品专注"从灵感到出发"这一段，**不做**行程中断救援 / 改签（那是行中/行后的方向，各有其适用场景，与本作互补而非对立）。
